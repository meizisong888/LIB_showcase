# Capstone usability evaluation plan

## Study goal

Evaluate whether Virginia Tech students, faculty, staff, and researchers can move from a real task to a defensible tool/workflow choice while recognizing data and verification boundaries.

## Participants

Recruit 12–20 participants across the four primary roles, including a mix of AI familiarity, assistive-technology use, disciplines, and administrative/research contexts. Do not use real restricted data in study tasks.

## Core tasks

1. **Find a tool in under two minutes.** Given a role, task, data class, output, and ecosystem, use Task Finder and choose a next step.
2. **Explain the recommendation.** State two positive factors, one trade-off, one non-use condition, and why an alternative is close or different.
3. **Recognize unsafe upload conditions.** Classify four sanitized scenarios and stop when the data class or approval is unclear.
4. **Complete work from one Skill card.** Prepare inputs, copy/customize the prompt, identify failure modes, and use the checklist on a synthetic output.
5. **Find an alternative.** Compare up to three tools or locate a related workflow when the first option lacks access or a required capability.
6. **Evaluate an installable skill.** Identify publisher, license, platform, file/network/command access, maintenance, and a reversible test plan.

## Success measures

| Measure | Target for MVP |
| --- | --- |
| Task Finder completion | ≥ 85% without moderator intervention |
| Appropriate tool or human-only decision | ≥ 80% |
| Completion time for first recommendation | Median ≤ 2 minutes |
| Correct explanation of recommendation reasons | ≥ 80% name two valid factors and a trade-off |
| Unsafe upload recognition | ≥ 90% stop on Unknown/Restricted ambiguity |
| Skill-card task completion | ≥ 80% produce the requested synthetic artifact and run checks |
| Alternative discovery | ≥ 85% find a viable alternative within 90 seconds |
| System Usability Scale (SUS) | Mean ≥ 80 |
| Critical accessibility barriers | 0 unresolved before final study round |

Also collect misclicks, backtracks, filter resets, comparison-limit confusion, unverified citation acceptance, confidence before/after, and comprehension of Product / Capability / Workflow Skill / Installable Skill.

## Procedure

1. Consent, role/context survey, and AI-familiarity baseline.
2. Think-aloud tasks in counterbalanced order using only synthetic/public materials.
3. Post-task single-ease questions and confidence rating.
4. SUS questionnaire and a short concept-comprehension check.
5. Semi-structured interview on trust, wording, missing conditions, and willingness to stop.

## Accessibility evaluation

Run expert and participant checks at 320 CSS px, 200% and 400% zoom/reflow, keyboard only, visible focus, screen reader landmarks/names/states, contrast, reduced motion, table navigation, form labels/errors, copy feedback, and mobile menu behavior. Include participants who use relevant assistive technologies; do not treat an automated scan as certification.

## Analysis and decision rules

Segment results by role and AI familiarity without making consequential claims from small subgroups. Prioritize:

1. Any path that encourages an unsafe upload or unsupported approval claim.
2. Task failure or inability to explain the recommendation.
3. Keyboard, screen-reader, zoom, or contrast blockers.
4. Repeated confusion between product, capability, and skill.
5. Time, wording, and visual-polish improvements.

Re-test critical fixes with at least three affected participants before final reporting. Preserve de-identified notes, task outcomes, timing, SUS scoring method, limitations, and deviations from this plan.
